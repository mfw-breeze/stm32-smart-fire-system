# 标定记录

> 所有阈值都来自实机测量，不是从别处抄的默认值。

## 1. MQ-2 预热

MQ-2 的敏感材料（SnO₂）需要加热到工作温度，读数才稳定：

```
上电 ──┬── 0~30s   ：读数从 3000+ 快速下降到 1200 附近，不可用于判断
       └── 30s 之后 ：漂移 < 2%/分钟，可以取基线
```

代码里的处理：

```c
OLED_ShowString(1, 1, "Warming up...");
for (i = 0; i < 30; i++) { OLED_ShowNum(2, 1, 30 - i, 2); Delay_ms(1000); }
Alarm_Init();          /* 预热完成后才建立基线 */
```

## 2. 基线怎么来的（1262）

洁净空气（室内、无烟、无香水）连续采样 10 分钟，取中位数：

| 时段 | 平均值 | 说明 |
|---|---|---|
| 预热后 0~1 min | 1278 | 仍在缓慢下降 |
| 1~5 min | 1263 | 基本稳定 |
| 5~10 min | 1262 | 稳定 |

**取 1262 作为典型本底**。但代码里并没有写死 1262 —— 它是运行时的自适应基线，
开机后自动学习当前环境的水平。1262 只是标定时用来推参数的参考值。

## 3. 阈值推导

```
margin  = baseline × 32% = 1262 × 0.32 = 404
触发点  = 1262 + 404 = 1666
```

为什么是 32%：

| 事件 | 读数峰值 | 是否应报警 |
|---|---|---|
| 室内正常 | 1262 | 否 |
| 香烟（1m 外） | 1700~2100 | 边缘（实测会进 `WARNING`，不会喷水） |
| 打火机放气 | 3000+ | 是 |
| 纸张阴燃 | 2600+ | 是 |

32% 让"香烟级别"落在 `WARNING`，让"明火级别"落到喷水区间。**这个百分比只能靠实测调**，
不同批次的 MQ-2 灵敏度能差一倍。

## 4. 迟滞为什么是 16%

```
release = baseline × 16% = 202
解除点  = 1262 + 202 = 1464
```

触发点 1666、解除点 1464，中间 202 的间隔就是迟滞带。
如果两者取同一个值，烟雾在 1666 附近抖动时状态会来回跳，继电器跟着"哒哒哒"响 —— 实机试过，
每分钟吸合 40+ 次，触点明显发热。

## 5. 温度判据

| 判据 | 阈值 | 依据 |
|---|---|---|
| 绝对超温 | 45°C | 室内环境上限，DHT11 量程 0~50°C |
| 升温过快 | 10s 内 +3°C | 早期火灾的热特征；空调/开门通常 <2°C |

两个条件取"或"：早期阴燃可能温度只到 38°C，但 10 秒涨 5°C，这时应该报。

## 6. 怎么重新标定（换传感器/换场地时）

1. 上电预热 **至少 30 秒**，等到读数不再快速下降
2. 洁净空气下记录 1 分钟的平均值 `B`（串口 CSV 第一列就是它，也可看 OLED 的 `B:`）
3. 用 **真的香烟/线香** 制造"应该预警但不该喷水"的场景，记录峰值 `P1`
4. 用 **纸张阴燃**（注意安全，在通风处）制造"应该喷水"的场景，记录峰值 `P2`
5. 令 `RISE_PCT ≈ (P1 + P2) / 2 / B × 100`，取整到 5 的倍数
6. 令 `FALL_PCT ≈ RISE_PCT / 2`，保证迟滞带足够宽（至少 200）
7. 改 `app/alarm_config.h`，重新跑 `make test`，再上机复测

## 7. 串口数据格式（用于回放分析）

```
S,B,T,H,STATE,Vdda
1262,1262,25,48,0,3298
```

| 字段 | 含义 |
|---|---|
| `S` | 当前烟雾原始值 |
| `B` | 当前基线 |
| `T` / `H` | 温度 / 湿度 |
| `STATE` | 0 正常 / 1 预警 / 2 火警 |
| `Vdda` | 内部参考电压（mV），用于判断供电是否稳 |

把这行 CSV 存成 `.csv` 就是一份可回放的测试数据，出问题可以直接对照时间点。
